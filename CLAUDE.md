# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

One-page marketing site for "Horizon Wealth Planning". Everything lives in `index.html`: CSS in a single `<style>` tag, JS in a single `<script>` tag. Hard constraint from the original brief: **plain HTML/CSS/vanilla JS only — no frameworks, build tools, package manager, or external JS**. Only external resources are Google Fonts (Playfair Display for headings, Inter for body), an Unsplash hero image, and randomuser.me avatars.

There is no build, lint, or test step. To run, open `index.html` directly in a browser.

Deployment: `.github/workflows/deploy-pages.yml` publishes to GitHub Pages on every push to `main`. It copies only `index.html` into `_site/`, so any new asset files must be added to its "Prepare site files" step. The repo's Pages source must be set to "GitHub Actions".

## Architecture of index.html

The file is split into numbered, commented sections that are kept in sync across HTML, CSS and JS. Follow the same pattern when adding features.

- **CSS**: design tokens are on `:root` (navy `#0B2545`, gold `#C9A227`, background `#F7F9FC`, spacing scale, radii, shadows). Use the tokens, not literal values. Styles are mobile-first: base rules target mobile, then `@media (min-width: 768px)` for tablet and `@media (min-width: 1024px)` for desktop. The desktop nav only replaces the hamburger at 1024px.
- **JS**: one IIFE in strict mode. It adds a `js` class to `<html>` first, and the `.reveal` fade-in styles are scoped under `.js`, so content stays visible if JS fails. `prefersReducedMotion` disables the counters, carousel autoplay and smooth scrolling.

Cross-cutting behaviours that span HTML, CSS and JS:
- **Scroll reveal**: add `class="reveal"` (optionally `delay-1..3`) to any element. One shared IntersectionObserver picks it up.
- **Stat counters**: `.stat-number` elements are driven by `data-target`, `data-prefix` and `data-suffix`. The real value is duplicated in a `.visually-hidden` span for screen readers.
- **Carousel**: the number of visible cards comes from the CSS custom property `--visible` on `.carousel` (1, 2 or 3, set per breakpoint). JS reads it with `getComputedStyle`, so change breakpoints in CSS only. Slides are the children of `#carouselTrack`. Dots, star icons and slide `aria-label`s are generated by JS. To add a testimonial, copy a `.carousel-slide` block and leave `.stars` empty. Off-screen slides get `aria-hidden` and `inert`.
- **Enquiry form**: validation is driven by the `validators` map (field name → function returning an error string). Each field needs a matching `<span id="{name}-error">`. The radio group (`contactMethod`) and the consent checkbox are special-cased in `getValue` and `showError`. Submission is simulated: there is a 1.5s spinner, the data is logged to the console as JSON, then `#formCard` is replaced with a success message. The user's name is inserted with `textContent`; keep it that way to avoid XSS.
- **Nav active state**: an IntersectionObserver over `main section[id]` matches each section to a nav link by its `href="#id"`. New sections need an `id` and a matching nav link.

Contact details (a Singapore address, phone number and email) are placeholders.
